# AI 读论文时最常丢的不是数字，是限定条件

> 一次以 CO₂ 地质封存论文为例的「证据定位式阅读」实践，附双提示对照、逐条原文核查与可复现脚本。

## 0. 阅读入口

- 正文：本文件 `README.md`
- 材料索引与版本：`提交说明.md`
- 提示词：`prompts/01-baseline.md`、`prompts/02-evidence-first.md`
- 论文片段与来源：`inputs/paper-metadata.md`、`inputs/excerpts.md`
- 两次真实输出：`outputs/baseline-answer.md`、`outputs/evidence-first-answer.md`
- 核查记录：`verification/check-record.md`、`verification/result.json`
- 复现：`reproduce.py`（真实运行日志 `run.log`）

## 1. 问题：为什么写这篇

读数值模拟类论文时，我最怕的不是看不懂，而是**把作者带限定条件的结论读成了无条件结论**。摘要为了简洁，往往把「压力场加速约 170 倍、饱和度场只加速约 7 倍」压成一句「从数小时降到数分钟」。

本次实践选一篇与我研究方向（CO₂ 驱替与油气藏相态数值模拟）相关的真实论文：

> Voulanas, D. & Gildin, E. (2025). Dynamic Mode Decomposition Accelerated Forecast and Optimization of Geological CO2 Storage in Deep Saline Aquifers. arXiv:2407.20541v4 (submitted 2024-07-30, revised 2025-03-28). https://arxiv.org/abs/2407.20541v4

**明确的阅读问题**：这篇论文声称把 CO₂ 封存模拟「从数小时降到数分钟」，这个说法在哪些条件下成立？哪些变量、哪些算例、哪些训练设置会改变这个结论？如果只让 AI 读摘要，会丢掉什么？

选题理由：该文摘要与正文之间存在多处**可逐字核查的粒度差**，适合做一个小而完整的对照，而不是泛泛谈「AI 读论文好用」。

## 2. 方法：从「摘要式提问」改成「证据定位 + 条件清单」

不是换更强的模型，而是换提问结构。同一模型、同一份输入材料，仅提示词不同。

| | Baseline（摘要式） | 证据定位式（本次方法） |
| --- | --- | --- |
| 输入 | 只有摘要（p1） | 摘要 + p3/p8/p12/p15/p16/p36 带页码原文片段 |
| 要求 | 「总结一下加速效果」 | 「逐条给数值 + 页码 + 原文引句 + 成立条件 + 未验证项」 |
| 输出约束 | 无 | 每个数字必须挂页码；区分「本文结果」与「文中引用他人结果」；单列局限 |
| 核查方式 | 无 | `reproduce.py` 逐页回查引句字符串 |

关键设计有三条，都来自实际踩过的坑：

1. **强制页码锚点**。要求每个数值后写 `pN`，并附一句原文。这样核查从「凭印象判断」变成「字符串匹配」。
2. **区分本文与引文**。论文 p3 文献综述引用了别的文献里「100,000 网格块 279→28 秒」的数字，与 p15–p16 的结果章节相隔十余页。不给这条约束，模型很容易把别人的加速比安到本文头上。
3. **单列「不成立/未验证」**。作者自己在 p36 写明只在一个油藏模型上做过、需要推广到多个油藏。把「作者自述局限」列为必需字段，能挡住「普遍适用」的过度概括。

取舍：证据定位式要多读 5 个片段、输出更长，但它把「加速多少」从一个形容词变成一张可复核的表。对需要照着做数值实验的人，这个代价值得；对只想快速筛选文献的人，Baseline 仍然够用。本文不声称「更快/更好」，只展示**信息完整度的差异**，且两次输出都原样保留在 `outputs/`。

## 3. 真实案例与结果

### 3.1 论文来源、版本与原文位置

- 版本：arXiv:2407.20541**v4**，49 页，PDF 从 `https://arxiv.org/pdf/2407.20541v4` 取得（2026-11-25 下载）。
- 授权说明见 `LICENSE-NOTE.md`；本文只提交足以核查结论的**合法片段**，不公开全文 PDF。
- 片段位置：p1 摘要、p3 引文、p8 模型设置、p12 训练/验证划分、p15 运行时间前半句、p16 跨页续句与 Table 1 标题、p36 平均值与局限。逐字片段见 `inputs/excerpts.md`。

### 3.2 实际使用的输入

- `inputs/excerpts.md`：7 段原文摘录（含页码），总计约 3 KB。
- 两次提示词全文：`prompts/`。
- 环境：Python 3.13 + PyMuPDF；模型 WorkBuddy（Tencent Hunyuan Hy），2026-11-25 执行。模型版本与成本如实记录：本次为对话内执行，未产生可单独计量的 API 账单，故不给出 token 成本数字。

### 3.3 两次真实输出与差异

两次输出**原样**保存在 `outputs/`，未做润色。核心差异：

| 核查点 | Baseline | 证据定位式 | 原文依据 |
| --- | --- | --- | --- |
| 加速比表述 | 「从数小时降到数分钟」 | 压力 ~1.28/1.4 min vs ~223/140 min；饱和度 ~33/31 min vs ~223/140 min | p15, p16 |
| 分变量差异 | 未提 | 明确压力与饱和度加速比相差约一个数量级 | p15, p16 |
| 算例差异 | 未提 | 区分 case A（单井注入）/ case B（注入+采水保压） | p15, p16, p36 |
| 网格规模 | 含糊 | 本文 >130,000 cells；并标注 p3 文献综述「100,000 网格块 279→28 秒」是**引用他人结果** | p1, p3 |
| 时间步设置 | 未提 | 5200 个 7 天步长、780 个注入/生产步、注入 15 年 + 监测 85 年 | p8, p12 |
| 训练/验证 | 未提 | ECLIPSE 300 runs 2/5/7/10 训练，用未参与训练的 runs 验证 | p12 |
| 局限 | 未提 | 作者自述仅一个高度非均质海上油藏，需在多个油藏验证；有地面设施/注入能力约束时精度可能下降 | p36 |

**最值得分享的发现**：Baseline 并没有「答错」，它把摘要复述得相当准确——问题恰恰在于**摘要本身是有损压缩**。当读者要据此设计自己的模拟实验时，丢掉的「饱和度变量只快约 7 倍」「单一油藏未推广」才是决定性信息。所以改进点不是让模型更聪明，而是把「证据定位 + 条件清单」写进提示词，并把页码锚点变成可自动核查的字符串。

### 3.4 核查、发现与局限

`verification/check-record.md` 逐条记录 11 个引句的页码核对结果，`reproduce.py` 真实运行后把机器核查结果写入 `verification/result.json`，日志见 `run.log`。

诚实的边界：

- 这是一次**单篇、单模型、单次**的定性对照，不是统计意义上的基准测试；不声称「普遍适用」或「稳定优于」。
- 两次输出由同一模型在本会话内生成，未做多次重复采样；因此不报告置信区间或平均得分。
- `reproduce.py` 核查的是**引句是否出现在指定页**，属于文本级校验，不等于复现了论文的数值实验。
- 论文 PDF 未随包提供，读者需按 `inputs/paper-metadata.md` 自行从 arXiv 获取；脚本在缺少本地 PDF 时会尝试下载。
- 未完成的验证不会写成已完成：本文没有重跑 ECLIPSE 300 或 DMD 训练。

## 4. 复现步骤与材料

```bash
# 1) 获取论文（与本次一致的版本）
curl -L https://arxiv.org/pdf/2407.20541v4 -o paper.pdf

# 2) 安装依赖
pip install pymupdf

# 3) 运行核查（脚本会逐页比对全部引句，输出 verification/result.json）
python3 reproduce.py

# 4) 人工复核
#    打开 verification/check-record.md，对照 inputs/excerpts.md 与 PDF 页码
#    检查每个数值是否挂了页码、是否区分本文结果与引文
```

结果检查方法：`result.json` 中每项 `"found": true` 表示该引句确实出现在标注页；任一为 `false` 即说明页码或转录有误。本次真实运行结果见 `verification/result.json` 与 `run.log`。

若要做同样的双提示对照，按 `prompts/` 两个文件分别向任意模型提问，输入用 `inputs/excerpts.md`，再按 `verification/check-record.md` 的表逐条打分即可。

## 6. 一句话结论

**给 AI 的提示词里加一栏「这个数字在哪一页、在什么条件下成立」，比换一个更强的模型更能防止读错论文。**
