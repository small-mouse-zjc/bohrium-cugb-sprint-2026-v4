# 方法说明（05）

## 1. 为什么用别名表对齐
正文写"学习率"，配置写 `learning_rate`，日志写 `lr`，三者指同一个参数。别名表把这些写法收敛到一个 key，`param_align.py` 才能同时抽正文值与来源值并比较。别名必须来自材料，不得臆造。

## 2. 四种状态
- `sourced`：正文值 = 某处来源值（浮点按数值比较，`1e-3` 与 `0.001` 视为相同）。
- `unsourced`：正文有值、来源全无 → 必须删或标"待确认"。
- `conflict`：正文与来源不同 → 以来源为准；来源彼此矛盾时全部列出。
- `omitted`：来源有、正文没写 → 关键参数必须补。

## 3. 为什么还扫"带单位的数值"
别名表只覆盖声明参数；正文里"25 °C""50 个岩心"这类数值可能根本没进表。脚本用单位词（%/MPa/°C/h/轮/层/维…）扫全文，凡是在所有来源里都找不到的，报 `unsourced_number`。这是防止"为段落顺畅补数值"的第二道网。

## 4. 步骤四要素
`输入 / 操作 / 输出 / 判断条件`。判断条件是复现的关键：没有它，读者不知道异常时该怎么办（例如"验证集连续 5 轮不降则停止"）。

## 5. 复现九项
代码版本、运行环境、依赖、硬件、数据获取、数据版本与划分、随机种子、启动命令、轮次与耗时。少一项就无法"照做得到同一产物"。

## 6. 已知边界
- 单位词表有限，非列表单位（如 μm、mL/min）不会被泛扫，需加入别名表或扩展词表。
- 只比对字面数值，不理解参数语义（如"衰减到 1e-5"与"初始 0.001"是两个参数）。
- 不判断实验设计是否合理，只判断"写的与材料是否一致、是否可复做"。
