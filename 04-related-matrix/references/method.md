# 方法说明（04）

## 1. 为什么先矩阵
逐篇写摘要的通病是"每篇都对，但读者不知道这些工作之间怎么比"。矩阵强制把每篇放到同一组维度上：问题设定、方法路线、数据与尺度、评价与指标、局限。填不满的格子会以 `gap_cells` 列出——那是**材料缺口**，不是研究空白。

## 2. 空白怎么推
规则写在 `scripts/matrix.py`：某局限被 ≥2 篇列为 `limits`，且没有任何一篇 `addresses` 它 → 候选空白，附支撑文献。
这保证空白是"由已引文献的缺口推出"，而不是"我觉得没人做过"。单篇局限不构成空白（`gaps` 为空时正文不许写"研究空白"）。

## 3. 分组与冲突
按 `route` 分组，组内比较取舍；同一 `claim_key` 出现 supports 与 opposes 时记为冲突，正文必须写条件差异（例如压力区间），不得选边。

## 4. 论断判定（用于挂引用检查）
句子满足以下任一即为"论断"，必须挂引用：含 `首次/表明/说明/证明/显示/优于/低于/高于/提升/降低/增加/减少/导致/因此/然而/相比/差异/空白/尚未/未覆盖/缺乏/缺少/没有/均未/未能`，且不以"本文"开头。
这是**偏严**的口径：宁可多要求一次引用，也不放过无依据断言。

## 5. 贡献核对
贡献条目必须形如"我们做了 X，证据见 §/Fig./Table N"，且 N 必须存在于 `manuscript.json` 的 sections/figures/tables 中。材料里没有的图，不能写成"见 Fig. 3"。

## 6. 已知边界
- 不判断转述是否"准确"到语义层，只核对 locator/quote 是否存在；语义准确性需人工抽检。
- 关键词法会漏掉无标志词的断言（如纯描述句），也会把带"没有"的背景句判为论断；口径偏严，需在 `uncertainties` 说明。
- 不生成真实文献；`works.json` 必须来自案例材料。
